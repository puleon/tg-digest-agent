Путь одного поста

Прежде чем разбирать каждую деталь, пройдём весь путь на одном настоящем примере. Пост 8648 из канала @am_devs — картинка без единого слова в тексте поста: на двери висит табличка «РЫБА / ПИВО / КОШКА». Посмотрим, что с ним происходит от момента, когда коллектор его увидел, до момента, когда бот процитировал его в ответе на «что-нибудь смешное про котов».

Шаг 1. Коллектор находит пост

У Telegram есть публичная веб-версия любого открытого канала: страница https://t.me/s/am_devs показывает 20 последних постов, а ?before=49720 — двадцать постов до сообщения 49720. Коллектор листает эти страницы назад, пока не дойдёт до постов полугодовой давности или до последнего уже собранного поста (глава 4).

На странице пост — это кусок HTML с атрибутом data-post="am_devs/49719". Из него коллектор достаёт номер сообщения, дату из тега <time datetime="2026-05-04T11:00:00+00:00">, счётчик просмотров («9.35K» превращается в 9 350), реакции и адрес картинки, спрятанный в CSS-свойстве background-image. Картинку он скачивает в папку медиа под именем, которое вычисляется из её адреса, — если тот же мем уже приходил из другого канала, файл не скачивается второй раз.

Шаг 2. Модель зрения читает картинку

Через два дня до поста дошла очередь обогащения. Ingest-агент (глава 6) видит: тема канала — юмор, у поста есть картинка, значит, её нужно описать. Картинка вместе с инструкцией уходит в модель зрения Gemma 4. Инструкция требует ответить строго в формате JSON с четырьмя полями:

{
  "ocr_text":    "РЫБА\nПИВО\nКОШКА",
  "caption":     "A humorous sign on a door lists fish, beer, and a cat,
                  implying the cat is also for sale or consumption.",
  "has_text":    true,
  "is_readable": true
}

OCR (optical character recognition) — распознавание текста на изображении. Подпись (caption) — одно предложение о том, что изображено и в чём шутка. Подпись по-английски, хотя просили описать «для русского индекса»: модель так решила, и это не страшно — модель эмбеддингов многоязычная (глава 8), и английское «cat» окажется рядом с русским «котом».

Шаг 3. Классификатор ставит метки

Затем текстовая модель Qwen3.6 получает всё, что известно о посте: текст (пустой), распознанный текст и подпись, — плюс восемь примеров правильной разметки. В ответ — снова JSON:

{"topic": "humor", "is_ad": false, "is_spoiler": false, "quality": 4}

Тема нужна для фильтров и дайджеста, реклама — чтобы её никогда не показывать, спойлер — для фильтра «без спойлеров», качество от 1 до 5 — чтобы дайджест не тратил места на пустые посты. Последний шаг агента — эвристика против промпт-инъекций: не адресует ли текст на картинке инструкции модели (глава 10). Здесь — нет.

Всё это записывается в таблицу enrichment вместе со строкой qwen3.6-35b-a3b+gemma-4-26b-a4b|classify_post.v1|vlm_describe.v1 — какие модели и какие версии промптов это сделали. Если завтра промпт поменяется, система будет знать, какие посты размечены старой версией.

Шаг 4. Поиск повторов

Мемы в Telegram копируют друг у друга, и одна и та же картинка может прийти из трёх каналов. Чтобы выпуск не показал её трижды, для каждого поста считаются подписи (глава 7): точный отпечаток файла SHA-256 и перцептивный хэш pHash — 64 бита, которые почти не меняются при пережатии и изменении размера картинки. У нашего поста pHash равен 0x68a69c629f389729, и ни у одного другого поста в корпусе нет хэша, отличающегося меньше чем в 7 битах. Значит, пост уникален и сам себе «представитель».

Шаг 5. Индексатор делает пост находимым

Чтобы искать по смыслу, текст превращают в вектор — список из 1 024 чисел, который описывает смысл так, что похожие по смыслу тексты дают близкие векторы (глава 8). Индексатор собирает для поста четыре текста — от «только текст поста» до «текст + OCR + подпись + выжимки ссылок» — и для каждого считает два представления: плотный вектор (смысл) и разреженный (важные слова с весами).

Зачем хранить все четыре варианта, если в работе используется только full? Чтобы измерить, сколько дают OCR и подписи: эксперимент гоняет одни и те же запросы по каждому варианту (глава 12). Для юмора разница огромная: по одному тексту постов находится треть того, что находится с описаниями картинок.

Вместе с векторами в Qdrant лежит payload — паспорт поста: тема, канал, дата, флаги рекламы и спойлера, качество, кластер дубликатов, ссылка https://t.me/am_devs/49719. По этим полям поиск фильтрует: «только юмор», «за последнюю неделю», «без рекламы».

Шаг 6. Вы спрашиваете — агент находит

Вы пишете боту «что-нибудь смешное про котов». Бот передаёт вопрос в API, API — поисковому агенту (глава 9), и дальше происходит вот что:

  1. route — модель определяет режим и фильтры: search, тема humor, без ограничения по дате;
  2. rewrite — модель предлагает три формулировки, как такое могло бы быть написано в посте: «смешные коты», «мемы про котов», «коты юмор»;
  3. retrieve — каждая формулировка ищется гибридным поиском по варианту full; списки сливаются в один (44 кандидата);
  4. grade — модель смотрит на десять лучших и для каждого отвечает «релевантен / нет»; в первый раз подошли только два — мало;
  5. rewrite_query — агент просит другие формулировки, сообщив модели, какие уже не сработали: «коты смешные», «мем кот»;
  6. второй круг retrieve → grade — теперь релевантны девять из десяти, среди них пост 8648;
  7. synthesize — модель пишет ответ, ссылаясь на посты в формате [post 8648]; код проверяет, что ссылки ведут на реально найденные посты.

В этом прогоне было 8 шагов, 5 203 токена и 15 минут — сервер параллельно обогащал корпус, и модель обслуживала обоих. На свободном сервере такой ответ занимает около двух минут. Где именно уходит время, разобрано в главе 9.

Шаг 7. Ваш голос возвращается в систему

Под постом в ответе бота есть кнопка 👍. Нажатие отправляет боту строку fb:l:8648:s:<id трейса> («лайк, пост 8648, из поиска, трейс такой-то»). Бот вызывает POST /feedback, API записывает голос в таблицу feedback и одновременно ставит оценку на трейс этого прогона в Langfuse (глава 14). При следующей пересборке профиля голос сдвинет веса тем и каналов и, возможно, центр одного из ваших «интересов» (глава 11).

Ключевая идея

Пост с пустым текстом нашёлся по запросу «коты» только потому, что ночью модель зрения записала слово «КОШКА» с таблички и подписала картинку. Дорогая работа (40 часов процессора на корпус) делается один раз и заранее, а дешёвая (поиск за доли секунды) — на каждый запрос. Почти вся архитектура проекта — это ответ на вопрос «что можно посчитать заранее».
